# LedgerShot 商户运营控制面上线手册

适用对象：值班、财务、风控。账本单位是 micro-USDC（1 USDC = 1,000,000）。控制面演练钟与生产时钟分开；不变量相同。

本手册对应的状态机：报价 → 冻结预授权 → 派发 → 结算，或退款 / 死信 / 核销。成功的请求才会写下幂等记录。结算暂停、冻结、余额不足、非法状态不会烧掉幂等键，同一回调可以在恢复后重放。

## 1. 上线门禁

- [ ] `npm test` 通过，合约测试与服务测试全绿
- [ ] `npm run typecheck` 与 `npm run build` 通过
- [ ] 演练账本对账结果为 0 条账差（BOOK_IMBALANCE / RESERVATION_DRIFT / SETTLED_FEE_MISMATCH / NEGATIVE_BALANCE）
- [ ] 死信队列有人认领，最老一笔预授权冻结不超过 30 分钟
- [ ] 平台费率已在预授权时锁定，结算不得改用新费率
- [ ] 回调验签密钥只放在服务端，控制面不展示完整密钥

未过门禁不得把演练费率或演练商户放进生产。

## 2. 发布与回滚

1. 先发只读控制面，确认总览、商户、任务账本、失败队列、可观测五页都能打开。
2. 用一笔 0.01 USDC 的静帧单走完报价、冻结、派发、结算。对账必须仍然平衡。
3. 再用一笔无效素材走永久失败，确认预授权全额回到可用余额，且同一幂等键的第二次回调是回放而不是第二笔退款。
4. 金丝雀先接 1 家低风险商户，观察 30 分钟。成功率低于 99.50% 或出现签名不匹配，停止扩容。
5. 回滚只回滚进程，不手改已结算分录。已结算的单用反向退款任务处理，禁止直接改余额。

## 3. 失败分类与补偿

| 错误码 | 类别 | 系统动作 |
| --- | --- | --- |
| RENDER_NODE_TIMEOUT / RPC_UNAVAILABLE / WEBHOOK_5XX | 暂时 | 最多 3 次，退避 30 秒起、封顶 15 分钟 |
| INVALID_ASSET / QUOTA_EXCEEDED / SIGNATURE_MISMATCH | 永久 | 立即全额退款，不重试 |
| 未登记错误码 | 未知 | 探测 1 次，第 2 次进入死信 |

永久失败里，SIGNATURE_MISMATCH 额外开 Sev2。先核对签名密钥与时钟，再决定是否冻结商户。不要为了“把单做完”改判成结算成功。

暂时失败的同一幂等键只计一次尝试。上游重试风暴不能把尝试次数打满。

## 4. 死信与值班

死信表示自动重试已结束，预授权仍冻结。30 分钟内必须三选一：

- 重试：商户未冻结时，把任务放回渲染中。再失败一次会重新进入死信。
- 退款：预授权回到商户可用余额。适合素材问题已确认、或商户要求停单。
- 核销：只用于无法退回的损耗。金额进入平台损耗，不进收入，也不进渲染池应付。

核销需要两个人中的第二个人在原因里写上工单号。演练环境用「值班-预览」即可，生产必须是实名。

## 5. 对账

每家商户永远满足：

期初 = 可用余额 + 冻结预授权 + 平台收入 + 渲染池应付 + 平台损耗

在途任务（已冻结、渲染中、死信）的报价合计必须等于冻结预授权。已结算任务满足：平台费 + 渲染池应付 = 报价，平台费 = 报价 × 锁定费率 bps / 10,000，向下取整。

对账失败时：

1. 停止新的结算与核销。
2. 冻结相关商户，避免账差被新单覆盖。
3. 按 traceId 导出状态迁移，找到第一笔让恒等式失败的事件。
4. 用反向业务动作修复，不直接改数。修复后对账必须回到 0 条。

控制面里的「注入 1 micro 账差」只会在对账视图上叠一只影子副本，用来确认告警是红的。它不写进正式账。

## 6. 商户管控

- 冻结：拒绝新的预授权，也拒绝结算。已冻结的钱留在原状态。解冻后回到冻结前的状态（营业或结算暂停）。
- 结算暂停：仍可接单、冻结、派发，但不能结算。预授权继续冻结。恢复后，原先被挡住的同一幂等键可以再次结算。
- 报价本身不冻钱。冻结商户仍可以报价，便于把拒绝留在预授权这一步。

高风险商户（跨境、灰盒）默认人工看死信，不自动核销。

## 7. 可观测与 SLO

- 目标：进入终态的任务里，结算成功或干净退款不低于 99.50%。死信和核销消耗错误预算。
- 每笔迁移都带 traceId、商户、任务、from、to、错误码。
- 幂等回放记审计事件 IDEMPOTENT_REPLAY，余额不得第二次变化。
- 拒绝类事件（余额不足、非法状态、合约校验失败）必须可见，但不能当成收入。

告警：

- 死信新增：Sev3，30 分钟未处理升级 Sev2
- 签名不匹配：Sev2，立即冻结可疑回调来源
- 对账非零：Sev2，停止结算
- 错误预算剩余低于 20%：停止金丝雀扩容

## 8. 事故响应

1. 值班在事件上点「缓解」，写明影响面：哪些商户、多少冻结金额、是否已经退款。
2. 需要止付时冻结商户，而不是关掉整个控制面。
3. 回调堆积时先看幂等回放比例。回放高、余额不变，是上游重试，不是重复扣款。
4. 关闭事件前再跑一次对账。对账不平，事件不能关。
5. 交接写三行：未关闭事件、最老死信、错误预算剩余。

## 9. 生产接入时不允许改的不变量

- 金额用整数 micro-USDC，接口拒绝小数。
- 幂等键 8 到 80 字符。同一个键配不同正文返回 IDEMPOTENCY_CONFLICT。
- 只有被接受的命令（ok）写入幂等记录。
- 结算拆分在预授权时锁定费率。
- 人工核销不等于退款，人工退款不等于核销。
