# LedgerShot 演练账本运营手册

适用范围：当前版本的应用内演练账本与运营控制台，供开发、测试和流程验证使用。账本单位是 micro-USDC（1 USDC = 1,000,000）。本手册描述的是模拟账本状态机，不代表真实商户资金、生产支付、生产 Webhook 或生产值班系统已经接入。

本手册对应的状态机：报价 → 冻结预授权 → 派发 → 结算，或退款 / 死信 / 核销。成功的请求才会写下幂等记录。结算暂停、冻结、余额不足、非法状态不会烧掉幂等键，同一回调可以在恢复后重放。

## 1. 演练发布门禁

- [ ] `npm test` 通过，合约测试与服务测试全绿
- [ ] `npm run typecheck`、`npm run lint` 与 `node scripts/with-app-env.mjs vite build` 通过
- [ ] 演练账本对账结果为 0 条账差（BOOK_IMBALANCE / RESERVATION_DRIFT / SETTLED_FEE_MISMATCH / NEGATIVE_BALANCE）
- [ ] 死信队列有人认领，最老一笔预授权冻结不超过 30 分钟
- [ ] 平台费率已在预授权时锁定，结算不得改用新费率
- [ ] 未来生产接入时，回调验签密钥必须只保存在服务端，控制面不得展示完整密钥

未通过独立安全审查、支付验证和生产环境验收前，不得将演练账本用于真实资金结算。

## 2. 发布与回滚

1. 启动演练控制台，确认总览、商户、任务账本、失败队列和可观测页面均可正常访问。
2. 使用演练数据模拟一笔 0.01 USDC 静帧任务，走完报价、冻结、派发和结算。对账必须仍然平衡。
3. 再用无效素材模拟永久失败，确认演练账本中的预授权全额回到可用余额，且同一幂等键的重复请求被识别为回放。
4. 使用模拟商户执行金丝雀演练，观察 30 分钟。演练成功率低于 99.50% 或出现签名不匹配时，停止后续演练并排查。
5. 演练回滚只恢复应用版本，不直接修改已结算分录。账本纠错应通过经过验证的反向业务操作完成，不应直接修改余额。

## 3. 演练失败分类与补偿

以下错误码和重试策略用于演练状态机；不表示当前部署已接入相应的外部渲染节点或生产 Webhook。

| 错误码 | 类别 | 系统动作 |
| --- | --- | --- |
| RENDER_NODE_TIMEOUT / RPC_UNAVAILABLE / WEBHOOK_5XX | 暂时 | 最多 3 次，退避 30 秒起、封顶 15 分钟 |
| INVALID_ASSET / QUOTA_EXCEEDED / SIGNATURE_MISMATCH | 永久 | 立即全额退款，不重试 |
| 未登记错误码 | 未知 | 探测 1 次，第 2 次进入死信 |

演练账本将 SIGNATURE_MISMATCH 记录为 Sev2 事件。先核对模拟签名配置与时钟，再评估是否需要冻结模拟商户。不要为了“把单做完”改判成结算成功。

暂时失败的同一幂等键只计一次尝试。上游重试风暴不能把尝试次数打满。

## 4. 死信与值班

死信表示自动重试已结束，预授权仍冻结。演练处置目标为 30 分钟内完成以下三种操作之一；当前代码不会自动计时升级：

- 重试：商户未冻结时，把任务放回渲染中。再失败一次会重新进入死信。
- 退款：预授权回到商户可用余额。适合素材问题已确认、或商户要求停单。
- 核销：只用于无法退回的损耗。金额进入平台损耗，不进收入，也不进渲染池应付。

演练核销操作要求在原因中填写工单号。当前代码未实现双人审批或第二人授权校验；生产接入前必须补充独立审批和操作人身份审计。

## 5. 演练账本对账

对每个模拟商户，演练账本必须满足以下余额恒等式：

期初 = 可用余额 + 冻结预授权 + 平台收入 + 渲染池应付 + 平台损耗

在途任务（已冻结、派发中、死信）的报价合计必须等于冻结预授权。已结算任务满足：平台费 + 渲染池应付 = 报价，平台费 = 报价 × 预授权时锁定的费率 bps / 10,000，向下取整。这些是应用内模拟账本的不变量，不代表链上 USDC 余额与该账本已实现自动对账。

演练对账失败时，操作人员应按以下步骤处理；这些步骤不代表系统会自动冻结商户或停止结算：

1. 停止新的结算与核销。
2. 冻结相关商户，避免账差被新单覆盖。
3. 按 traceId 导出状态迁移，找到第一笔让恒等式失败的事件。
4. 用反向业务动作修复，不直接改数。修复后对账必须回到 0 条。

控制台中的「注入 1 micro 账差」会对演练账本创建独立副本并增加 1 micro，用于验证对账异常展示；不会修改正式演练账本。

## 6. 演练商户管控

- 冻结：拒绝新的预授权，也拒绝结算。已冻结的钱留在原状态。解冻后回到冻结前的状态（营业或结算暂停）。
- 结算暂停：仍可接单、冻结、派发，但不能结算。预授权继续冻结。恢复后，原先被挡住的同一幂等键可以再次结算。
- 报价本身不冻钱。冻结商户仍可以报价，便于把拒绝留在预授权这一步。

演练中可对模拟商户执行冻结和结算暂停。当前规则不构成真实商户风控能力；生产接入仍需独立的商户身份、风险评估、权限和审计机制。

## 7. 演练指标与事件记录

- 演练目标：按应用内统计口径，成功结算或退款的终态任务比例达到 99.50%。该指标仅用于演练数据分析，不是生产 SLO 或服务可用性承诺。
- 账本状态迁移事件记录 traceId、商户、任务、from、to 和事件代码；具体字段以事件类型为准。
- 幂等回放记审计事件 IDEMPOTENT_REPLAY，余额不得第二次变化。
- 拒绝类事件（余额不足、非法状态等）用于演练审计，不得计入收入。链上交易验证结果应与演练账本事件区分。

演练事件等级与处理规则（当前为控制台内记录，不代表外部监控或通知系统已接入）：

- 死信新增：演练事件标记为 Sev3；30 分钟处置时限目前是人工目标，不代表系统自动升级
- 签名不匹配：演练事件标记为 Sev2；生产环境的来源隔离和告警需要单独实现
- 对账非零：演练事件按 Sev2 处理，暂停后续演练结算
- 演练错误预算剩余低于 20%：停止后续演练

## 8. 演练事件处理

1. 在控制台事件上选择「缓解」，记录受影响的模拟商户、冻结金额及退款状态。
2. 演练中需要阻止后续预授权或结算时，冻结对应模拟商户，而不是关闭整个控制台。
3. 分析重复请求时检查幂等回放事件；回放不会再次改变演练账本余额。当前演练不代表真实上游 Webhook 已接入。
4. 关闭演练事件前由操作人员重新运行账本对账；存在未解决账差时，不应关闭事件。当前事件关闭操作不等于自动对账审批。
5. 演练记录应包含未关闭事件、最早进入死信的任务和当前错误预算。

## 9. 未来生产接入必须保留的不变量

- 金额使用整数 micro-USDC，接口拒绝小数；生产接口必须继续保持这一约束。
- 幂等键长度为 8 到 80 个字符。同一个键对应不同请求正文时返回 IDEMPOTENCY_CONFLICT。生产接入必须保留该约束。
- 只有被接受的命令（ok）写入幂等记录。
- 结算拆分在预授权时锁定费率。
- 人工核销不等于退款，人工退款不等于核销。
